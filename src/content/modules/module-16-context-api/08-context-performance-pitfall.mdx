# Context Performance Pitfall

If you put an object with 10 properties in context and update just 1 property, EVERY component calling `useContext` re-renders, even if it only uses an unchanged property!

### Key Concepts & Rules:

- Split unrelated state into separate contexts (e.g. `ThemeContext` vs `AuthContext`).
- For high-frequency updates, use Zustand selectors instead.

### Code Example: Context Splitting Strategy

```tsx
// ⚠️ Bad: Bundling high-frequency state with low-frequency state:
// <BigContext.Provider value={{ user, timerSeconds, theme, searchResults }}>

// ✅ Good: Split contexts by concern:
// <AuthProvider><ThemeProvider><App /></ThemeProvider></AuthProvider>
```
